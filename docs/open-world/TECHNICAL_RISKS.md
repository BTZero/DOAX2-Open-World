## Conditions requiring a scoped design decision

- If Niki Beach has no reusable collision outside a small area, stop expansion at verified bounds. Present the measured extent and cost of authoring collision; do not silently remove boundaries or count a visual plane as ground support.
- If actor initialization requires a full match, first determine which dependencies can remain without competition. A timer-frozen match with opponents is not Phase 1 acceptance.
- If no safe original teardown/return path is known, do not permit experimental entry. Process termination does not fulfill repeatable exit requirements.
- If an animation is a movie or inseparable scripted sequence, catalog it as unsuitable for a locomotion loop until another resource is verified.
- If runtime testing cannot be performed, record static/build-only results and leave the relevant acceptance item unverified.

## Current blockers versus hypotheses

**Confirmed blockers now:** SDK preparation/install, development input-path preparation, missing generated code and no runnable baseline. **Unresolved feasibility gates:** Niki Beach initialization/teardown, player creation and animation control, terrain queries, camera ownership, autosave/calendar separation. These may be solvable; the current evidence does not establish that they are impossible.

## Validation policy

Each implementation task must report source/hash/profile, build and linker results, actual runtime scenarios exercised, limitations and performance observations. A successful compiler run does not establish collision, original-mode compatibility, correct animations or safe saves. Use original user-data isolation throughout experimentation; no original save modification is authorized by this plan.
